Disabled
The button does not resize while it works. A commit button that shrinks to a spinner shifts everything beside it, and on a slow connection the user has already moved the pointer. The label's width is held and the spinner is drawn inside it.
Disabled needs a reason nearby. A disabled primary action is only acceptable when the page says what would enable it — “Approve” disabled while critical warnings are unacknowledged, with the acknowledgement directly above it. A disabled button with no explanation is a dead end.

Field sizing

52px controls · 56px camera and confirmation
Field actions are full-width and stacked in decision order, with the destructive-to-the-flow option last. The manual route is always visible rather than hidden behind an overflow, because it is a legitimate path and not a failure. Minimum 48 × 48px for every field target. Camera and confirmation actions get 56px because they are pressed while the operator is also holding the phone steady.

Action pairing

Do — one primary, ordered by consequence
Reject is reachable but visually distinct, so it is never pressed by muscle memory.
Don't — competing emphasis
Two filled buttons side by side, one of them irreversible. The eye cannot tell which action the page expects, and the riskiest option is the most visually prominent.
✓Labels are direct and name the outcome: “Submit for approval”, “Return for recapture”, “Retry sync”. Never “Process”, “Okay” or “Done”.
✓An action keeps its name through the whole flow — the button that says “Commit valid rows” produces a result that says “Committed”.
✓Sentence case throughout. No title case, no all-caps button labels.
✓Irreversible actions confirm in a dialog that names the consequence, not a generic “Are you sure?”.
