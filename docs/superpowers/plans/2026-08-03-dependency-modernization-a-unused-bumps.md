# Dependency Modernization Piece A — Unused Dependency Bumps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the four declared-but-unimported dependencies to their current majors — `fl_chart`, `csv`, `google_mlkit_face_detection`, `workmanager` — reducing the modernization backlog from seven migrations to three.

**Architecture:** Four one-line edits to `pubspec.yaml` across three commits, grouped by risk: the pure-Dart pair together, then each native plugin alone so a Gradle regression is attributable to a single revertible commit. No code, documentation or test changes — nothing in the repo imports these packages, so the build succeeding is the verification.

**Tech Stack:** Flutter 3.44.8 · Dart 3.12.2 · Gradle Kotlin DSL / AGP 9.0.1 · GitHub Actions (`gate` job, required check on `main`)

**Spec:** [`../specs/2026-08-03-dependency-modernization-a-unused-bumps-design.md`](../specs/2026-08-03-dependency-modernization-a-unused-bumps-design.md)

## Global Constraints

Every task's requirements implicitly include this section.

- **Only two files may change in this entire plan: `pubspec.yaml` and `pubspec.lock`.** Any other modified file is a defect. Done-criterion 6 of the spec.
- **`pubspec.lock` is committed in the same commit as the pubspec change that caused it** — three commits means three lockfile updates. `--enforce-lockfile` must hold at *every* commit, not just at the end, or bisecting into a commit fails for the wrong reason.
- **No `minSdk`, `compileSdk`, `ndkVersion`, manifest or Gradle changes.** `android/app/build.gradle.kts` pins `minSdk = 24`, `compileSdk = 36`, `targetSdk = 36`, `ndkVersion = "28.2.13676358"`. If a bump demands a change to any of these, **STOP and report** — see each task's stop rule.
- **No new tests.** All four packages are unused; a test asserting anything about them would assert nothing real. Spec §5 states this explicitly. Do not invent coverage.
- `flutter analyze --fatal-infos` must exit 0 with `No issues found!`.
- `flutter test` must pass **37** tests.
- `dart format --output=none --set-exit-if-changed .` must exit 0.
- Never `git add -A` or `git add .`. `.claude/` is intentionally untracked and must stay so; `git status --porcelain` must show only `?? .claude/` after each commit.
- Do not push. Task 4 handles that and requires explicit user authorization first.
- Branch is `feat/campaign-management-flutter-scaffold`; HEAD at plan time is `c71f78a`. Do not create branches or PRs.

## Task 1: Bump the pure-Dart pair (`fl_chart`, `csv`)

Zero-risk group: both packages are pure Dart and imported nowhere, so they are tree-shaken out of every build.

**Files:**
- Modify: `pubspec.yaml:55` (`fl_chart`), `pubspec.yaml:59` (`csv`)

- Produces: `fl_chart` at `^1.2.0` and `csv` at `^8.0.0` in `pubspec.yaml`, with a lockfile that satisfies them. Tasks 2 and 3 build on this lockfile state.

Expected: `no imports - expected`.

If this returns any hit, **STOP and report**. The spec's entire premise is that these are unused; a real import means a migration is required and this task's zero-risk framing is wrong.



- [ ] **Step 3: Resolve and inspect what moved**

Run:
```bash

```
Expected: succeeds. Then confirm the resolved versions:

Expected: `fl_chart` resolves to `1.2.0` and `csv` to `8.0.0`.
